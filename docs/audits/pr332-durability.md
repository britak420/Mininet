## Implemented

- `mini-durable`: stable OS file locks; unique create-new temporary files; flush file contents before rename and containing directory afterward. Windows opens directories for write with `FILE_FLAG_BACKUP_SEMANTICS`; unsupported/failed barriers return errors. `FsBackend` now uses this primitive for blobs and metadata and commits newly created ancestor entries.
- F-04: a domain-tagged checksummed author-bound `sequence.head` reserves each counter value before the legacy counter mirror is replaced. Counter/checkpoint mismatch, isolated deletion, corruption and exhaustion refuse signing. Every CLI allocation also checks genuinely signed local-author object sequences in the selected store. Unauthenticated author labels cannot raise the floor.
- F-05/F-06: witness v2 records retain original receipt bytes plus the ordered observations and transition certifications that generated them. Recovery replays the state machine and requires exact receipt equality. The signing key is bound by stored signatures. A lifetime process lock excludes other services; bounded reads, per-identity/aggregate byte caps and startup identity quotas apply. A failed persistence operation poisons the instance until reopen. Identical certification retries return the original receipt. Both certification and ordinary observation refuse a conflicting certified successor. Transition verification cross-checks the old policy against the verified KEL predecessor prefix.
- F-09: intake add/advance/publish share one home-level OS lock. Journals are bounded, durably committed before insertion, and authenticated against local root/device provenance and exact signed intake/source binding before recovery. Existing publication links are checked against the stored object. Object/envelope durability is re-established before recovery-journal deletion, whose directory barrier is fallible.
- F-12: replay mutations reload disk state under a process lock. Checksummed v2 lines bind identity, nonce and record time. Every complete malformed line fails closed, even the final line; only an unterminated tail is recoverable. File/directory barriers precede acceptance. A separate checksummed time floor is committed before pruning and rejects backwards wall-clock movement. `try_check_and_record` exposes storage errors; the trait adapter refuses on errors. Runtime deletion does not silently recreate state.

## Recovery, migration, and limits

- Witness v1 records lack original receipts and past transition commitments. Startup deliberately returns `MigrationRequired`. Keep the original directory and signing key offline, reconcile previously released receipts/certifications with counterparties or independently retained witness history, and prepare an exact reviewed import. No automatic migration or safe key-rotation importer is implemented. Starting the old signer with an empty directory is unsafe.
- Witness write errors require dropping/reopening the service, preserving both the final record and temporary evidence. A post-rename error may already have committed; never retry from stale memory.
- Sequence checkpoint mismatch requires reconciling the highest issued/reserved value against retained signed-author history. Do not delete the checkpoint or reset the counter. A crash between the two files can reserve an unused number and require recovery; gaps are preferable to reuse. Legacy valid counters without a checkpoint are adopted only after checking the available signed-store floor.
- Replay legacy complete records are converted under the process lock to v2; preserve damaged logs and do not erase them to bypass a failed load. Correct a backwards clock only against trusted time before reopening. Retention must cover the full permitted attestation freshness window.
- Locks require cooperating writers, stable lock-file names, and owner-controlled local directories. Administrative deletion, symlink/path replacement, remote filesystems ignoring locks or flushes, and restoration of every local checkpoint together are outside these guarantees. Whole-state rollback requires independently retained monotonic checkpoints. Store author-index loss can hide signed history; the separate reservation checkpoint remains necessary.
- A filesystem flush request is not a destructive power-cut campaign. Physical power-loss fault injection across supported operating systems/filesystems/devices, cross-store transaction/index recovery, witness history compaction and migration, and external semantic/cryptographic review remain production work. F-06 consumers still need a policy requiring authenticated transition continuity where authority depends on it.

Next bottleneck: complete fault-injection and platform test evidence, supply reviewed legacy/key-epoch recovery mechanisms, and bind high-value consumers to retained authenticated history. Do not call these findings universally closed from this implementation alone.
